# Signed URLs

Files in S3 are private. Access is via time-limited **signed URLs** generated by `IS3Helper.GeneratePresignedGetUrlAsync(key, ttl)`.

## Default TTL

15 minutes. Configurable per-product:

```csharp
builder.Services.AddChthonicFiles(opts => opts.SignedUrlTtl = TimeSpan.FromHours(2));
```

Values longer than 7 days are rejected at startup (S3 max lifetime for SigV4 presigned URLs).

## Generation

```csharp
public class FileService(IS3Helper s3, IDbContext db)
{
    public async Task<string> GetSignedUrlAsync(int fileId, TimeSpan? ttl = null)
    {
        var file = await db.Files.FirstAsync(f => f.FileId == fileId);
        ttl ??= _opts.SignedUrlTtl;
        if (file.S3Key is not null)
            return await s3.GeneratePresignedGetUrlAsync(file.S3Key, ttl.Value);
        // Legacy DB-blob fallback
        return $"/api/files/{file.FileId}/raw";
    }
}
```

## Frontend regeneration

Browsers cache the URL for the TTL. After expiry, the next `<img src>` fetch fails. `<FileGallery>` handles this:

1. On render, request a fresh URL from `/api/files/{id}/url`.
2. Use the URL until the TTL expires.
3. If a load error fires (HTTP 403 from S3), refetch.

## Regeneration policy

- **Authenticated** consumers: short TTL (15min) is fine.
- **Sharable links** (e.g. customer-facing invoice download): longer TTL (7 days max). Generate via `GetSignedUrlAsync(fileId, TimeSpan.FromDays(7))` per request.
- **Public** content (logos, public listing media): use a separate non-private S3 path or CloudFront with public-read. The library doesn't manage public access — that's a separate flow.

## Endpoint

```
GET /api/files/{id}/url
Authorization: Bearer <token>

→ 200 OK
{
  "url": "https://torque-tech-media-prod.s3.ap-southeast-1.amazonaws.com/...?X-Amz-...",
  "expiresAt": "2026-05-22T03:30:00Z"
}
```

## Avoiding repeated signing

For pages with N files, signing N URLs server-side has overhead. Two strategies:

1. **Bulk endpoint**: `POST /api/files/urls` with `[fileIds]` returning a map. Implemented as needed.
2. **Cache in-flight**: short-lived in-memory cache (60-second TTL) keyed by `file_id`.

The library doesn't ship a bulk endpoint at v0.1.2. Add to `FileEndpoints` + open a follow-up issue if you need it.
